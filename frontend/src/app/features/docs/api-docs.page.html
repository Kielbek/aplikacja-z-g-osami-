Narrivy API · v1

Zamieniaj tekst na mowę z własnych aplikacji

REST API z tymi samymi głosami i jakością co edytor Narrivy: 21 głosów z biblioteki, Twoje głosy zaprojektowane i sklonowane, 30 języków, emocje i styl mówienia.

  • Adres bazowy{{ base }}/v1
  • FormatJSON (pola w snake_case), odpowiedzi audio jako MP3 lub WAV
  • Dostępplany Pro i Business
  • Rozliczanieznaki z API liczą się do miesięcznego limitu planu, a po jego wyczerpaniu — do dokupionych pakietów

Każde nagranie zawiera w metadanych pliku oznaczenie treści wygenerowanej przez AI (zgodnie z art. 50 AI Act). Maszynowy opis API w formacie OpenAPI 3.1 znajdziesz pod /v1/openapi.json — zaimportujesz go do Postmana, Insomnii lub generatora klientów.

Klucz trzymaj wyłącznie na serwerze. Nie umieszczaj go w kodzie strony, aplikacji mobilnej ani w repozytorium. API nie obsługuje wywołań z przeglądarki (CORS) — to celowe. Jeśli klucz wycieknie, unieważnij go w ustawieniach i utwórz nowy.

Synteza mowy

POST/v1/text-to-speech

Synchroniczna synteza tekstu do 5 000 znaków. Odpowiedzią jest plik audio (audio/mpeg lub audio/wav). Dłuższe teksty dzielimy automatycznie na części po zdaniach i łączymy w jedno nagranie — ale powyżej limitu użyj zadań w tle.

Zadania w tle

POST/v1/text-to-speech/jobs
GET/v1/text-to-speech/jobs/{{ '{' }}job_id{{ '}' }}
GET/v1/text-to-speech/jobs/{{ '{' }}job_id{{ '}' }}/audio

Dla długich tekstów — audiobooków, kursów, artykułów — do limitu znaków w projekcie z Twojego planu (Pro: 100 000, Business: 500 000). Treść żądania jest taka sama jak przy syntezie synchronicznej, opcjonalnie z callback_url. Odpowiedź 202 Accepted zawiera opis zadania i nagłówek Location.

  • Statusy: queued → processing → succeeded lub failed (z polem error).
  • Idempotencja: wyślij nagłówek Idempotency-Key (np. UUID lub identyfikator rozdziału). Ponowione żądanie z tym samym kluczem zwróci istniejące zadanie zamiast tworzyć drugie — bezpiecznie ponawiaj po błędach sieci.
  • Przechowywanie: wynik i opis zadania są dostępne przez 7 dni (expires_at), potem są usuwane.
  • Kolejność na GPU: zadania w tle ustępują pierwszeństwa syntezie synchronicznej — czas oczekiwania zależy od obciążenia.

Przykładowa odpowiedź

Webhooki

Jeśli podasz callback_url, po zakończeniu zadania wyślemy na ten adres żądanie POST ze zdarzeniem job.succeeded lub job.failed. Adres musi używać https:// i wskazywać serwer publiczny.

Weryfikacja podpisu

Nagłówek Narrivy-Signature ma postać t=<czas unix>,v1=<podpis>, gdzie podpis to HMAC-SHA256 z tekstu t + "." + treść, kluczem jest sekret webhooków z Ustawienia → API. Odrzucaj zdarzenia z niepoprawnym podpisem lub starsze niż 5 minut.

Ponowienia

Odpowiedz kodem 2xx w ciągu 10 sekund. W przeciwnym razie ponowimy wysyłkę po 10 s, 1 min, 5 min i 30 min (łącznie 5 prób). Zdarzenia mogą wyjątkowo dotrzeć podwójnie — rozpoznasz je po polu data.id.

Dobre praktyki

  • Ponawiaj z odstępem przy 429 i 503 — odczekaj tyle sekund, ile podaje Retry-After; nie ponawiaj błędów 4xx z innymi kodami.
  • Długie teksty wysyłaj jako zadania z Idempotency-Key i webhookiem zamiast trzymać otwarte połączenie.
  • Osobny klucz dla każdej aplikacji — łatwiej śledzić zużycie (widać je przy każdym kluczu) i unieważnić tylko jeden.
  • Buforuj nagrania — ten sam tekst z tym samym seed brzmi tak samo, więc nie generuj go ponownie.
  • Sprawdzaj X-Engine-Mode — wartość demo oznacza sygnał zastępczy (np. podczas przerwy technicznej modelu).
  • Pamiętaj o zgodach — głosy sklonowane możesz wykorzystywać tylko zgodnie ze zgodą właściciela głosu złożoną przy klonowaniu.
